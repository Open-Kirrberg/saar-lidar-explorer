# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is the `zones/schloss-karlsberg/` sub-project of the Saar LiDAR Explorer; the parent `../../CLAUDE.md` (explorer app, pipeline, licences, heritage rules, commit style) also applies. It is a researched, georeferenced 3D reconstruction of Schloss Karlsberg as of summer 1789: a procedural generator, a standalone three.js viewer (Fliegen/Gehen), and generated plan sheets. Everything it produces is a **hypothesis** with evidence tags and confidence levels.

Docs to read before non-trivial changes:
- `README.md`: short status, run, viewer keys, layout. `CHANGELOG.md`: **one line** per shipped change. `docs/improvement-backlog.md`: open items only. Decisions are ADRs in `../../docs/adr/` (never edited once accepted; see ADR 0025). The pre-2026-11-04 long forms are frozen in `docs/history/` — read, never extend.
- `docs/architecture.md`: the **binding contract** between core, exterior, interior, site, viewer and plans (frames, sides, storeys, LOD, materials, naming, builder rules). If you change an API it lists, update it in the same commit. Note: its §2 ownership table predates implementation (work packages, not people); everything listed there exists.
- `docs/explorer-integration.md`: the `sle-recon-v1` light layer and the camera handover with `../../app`. The explorer side is in `../../docs/data-contract.md`.
- `plans/README.md`: the sheet list and drawing conventions.

## Commands

```bash
pnpm install
pnpm run dev                     # viewer, http://localhost:5260/ (not 127.0.0.1: Vite binds [::1] on macOS)
pnpm run test                    # vitest over model/tests, plans/tests, viewer/tests
pnpm exec vitest run model/tests/frame.test.ts      # single file
pnpm exec vitest run -t "round trip"                # by test name
pnpm run build                   # tsc --noEmit + vite build → dist/   (test + build are the gates)
pnpm run plans [--only GR-01 --no-pdf]              # sheets → plans/out/, PNG previews → docs/plans-preview/ (headless Chrome via CHROME_BIN)
pnpm run export                  # per-building glTF lod0/1/2 → model/out/
pnpm run export:explorer         # light layer → ../../app/public/data/shared/karlsberg1789/ (needs viewer/public/terrain/)
pnpm run textures                # CC0 Poly Haven sets → viewer/public/textures/ (manifest viewer/textures.json)
pnpm exec tsx scripts/catalogue-v2/build.ts         # regenerate model/catalogue.json (deterministic)
pnpm exec tsx scripts/dev/ray.ts                    # diagnostics: raycasts through facade openings
pnpm exec tsx scripts/dev/warn.ts                   # diagnostics: interior warnings
# Python steps use the pipeline's uv env and read ../../data/work read-only:
cd ../../pipeline && uv run python -I ../zones/schloss-karlsberg/scripts/prepare-terrain.py        # viewer terrain (1789 + 2025)
cd ../../pipeline && uv run python -I ../zones/schloss-karlsberg/plans/scripts/terrain.py          # plans/data/ underlays
cd ../../pipeline && uv run python -I ../zones/schloss-karlsberg/scripts/catalogue-v2/sample_dtm.py # then rebuild the catalogue
```

Ports: viewer dev on 5260 and preview on 5261. 5240 is the explorer dev server and 5250 is the explorer's `serve:local`, so don't use them for the viewer.

## Architecture

There is one pnpm package with three entry points sharing `model/src`, which is aliased as `@model` in Vite and tsconfig. Imports use explicit `.ts` extensions.

```
model/catalogue.json (v2, generated by scripts/catalogue-v2/; catalogue.v1.json = frozen test fixture)
  → catalogue.ts loadSite(): validate → upgradeV1 → validate(v2) → SiteSpec (spec.ts)
  → layout/  PURE, no three: layoutBuilding(b, spec) → BuildingLayout  ← the single truth
       ├─ exterior/ buildExterior   ┐
       ├─ interior/ buildInterior   ├─ three.js Groups, via BuildContext (context.ts: lod, materials, terrain, memoised layout)
       ├─ site/     buildSite       ┘  → viewer/ (fly + walk, three-mesh-bvh colliders)
       ├─ explorer/export.ts + scripts/export-explorer.ts → sle-recon-v1 for ../../app
       └─ plans/src (SVG/PDF, never three) ← same layout + interior/stairPlan.ts, so plans can't disagree with 3D
```

Rules that follow from this:
- Pure logic lives in `model/src/layout`, `frame.ts`, `spec.ts`, `validate.ts` and `catalogue.ts`. It never imports three.js and it is unit-tested. A builder that needs a new geometric helper adds it in `layout/` with a test; it does not re-derive frames, axes, heights or openings locally.
- Builders start from `ctx.layout(b)`, skip unplaced buildings (`isPlaced`), and skip `placement === 'hypothetical'` unless `showHypothetical` is set.
- Period norms (window sizes, axis spacing, roof ratios, stairs) live only in `layout/grammar.ts` with their evidence tag. Don't hard-code numbers in consumers.
- Facts about specific buildings belong in the catalogue (via `scripts/catalogue-v2/`), not in code. `scripts/catalogue-v2/checks.ts` checks that no partition wall hits a window.
- Randomness is deterministic: `mulberry32(hashString(id) ^ ctx.options.seed)`.

## Conventions that bite

- **Frames:** use local `x = E − 381000`, `y = h`, `z = −(N − 5465000)`, with true heights in DHHN2016 and **no exaggeration** (the explorer applies it). Building groups use object space `(s, h, −t)`, where `+t` points out of the **court** side, under `position = originLocal` and `rotation.y = rotationY`. Never put raw UTM into float32.
- **Azimuths** are measured from grid north; `true = grid + γ`, with γ ≈ −1.23°. The palace grid axis is at 80.5°.
- **Sides:** `p0` is the left end of a side seen from outside, and facade positions `a` are metres from `p0`. Storey indices include the plinth everywhere (rooms, openings, portals, stairs).
- **Naming:** objects are named `<buildingId>/<part>[/<detail>]`, with `userData` set to `PartUserData`. Materials are named `<surface>.<variant>` from `MATERIAL_NAMES`, and glb exports keep those names.
- **Terrain-buried openings** are culled with the shared `cullBuriedOpenings` in both the exterior and the interior. Interior reveals must lie inside their exterior holes, and a test enforces this.
- **Evidence:** don't invent sources. Derived values get tag `I`, and HMS-derived numbers get tag `HMS`. **No HMS video frames or textures go into the model** (© Matzerath / Historisches Museum Saar).
- **UI** labels and `name_de` are German; code and docs are English. The viewer shows confidence and "Schauen, nicht graben".
- **Viewer test hooks:** `window.skb` provides `goto`, `step`, `set`, `gpuBench`, `handover` and `backUrl`. Automated Chrome tabs are often hidden, so drive frames with `skb.step(n)`. Rendering changes need a browser check with screenshots; shots stay in the git-ignored `docs/shots/`, and an image is committed only if a doc links it.
- **Handover URLs:** `?src=explorer&E=…&N=…&h=…&heading=…&pitch=…&mode=fliegen|gehen&back=…`. `back` must be validated as a local URL (`viewer/src/handover.ts`).
- **Git-ignored and regenerable:** `sources/`, `viewer/public/textures/`, `viewer/public/terrain/`, `plans/data/`, `plans/out/`, `model/out/`, `dist/`, `docs/shots/` (backlog before/after shots), `docs/plans-preview/`, and video2world inputs and outputs. Keep data and media out of git. Dependencies are pinned to exact versions.
