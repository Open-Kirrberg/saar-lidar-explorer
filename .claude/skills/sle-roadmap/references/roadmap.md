## R0 — Hardening (do first; small, makes everything after safer)

- [x] (9f73ce4) **R0.1 Live local relief built from half-loaded mosaic** — `app/src/terrain/Terrain.ts` (~617–645, 188): `ensureLowpass` can run while chunks are still loading (heights = 0) and is never rebuilt → later chunks show solid red. Fix with a **generation counter** bumped at the end of `load()` (a plain `lowpassBuiltFor = -1` reset races with a build already in flight, which would overwrite it), or only build once all chunks are loaded. Test: switch to `5`/Shift+4 during "Lade Gelände …".
- [x] (9f73ce4) **R0.2 Canopy missing for chunks loaded after forest was enabled** — `Terrain.ts` (~515, 189): after `canopyPending` resolves, re-check for chunks without canopy and load them.
- [x] (9f73ce4) **R0.3 GeoJSON import puts markers at UTM (0,0)** — `app/src/markers/markerStore.ts` (~164): `Number(null)`/`Number('')` = 0 passes `isFinite`. Require real numbers or fall back to geometry. Add unit test with QGIS-style null/empty properties.
- [x] (9f73ce4) **R0.4 URL hash robustness** — `app/src/state.ts` (~113, 148): wrap `decodeURIComponent` in try/catch (malformed `%` hangs startup); validate layer with `terrain.isValidDisplay` before writing to the store.
- [x] (9f73ce4) **R0.5 LOD cracks at high exaggeration** — skirt depth is set per chunk in `TerrainChunk.ts` (~109) and applied in `terrain.vert.glsl` (~18); the culling margin (−30 m) is in `TerrainChunk.bounds()` (~134). Scale the **terrain** skirts with exaggeration (`uSkirtDepth * max(uExag, 1.0)` or set per chunk on exaggeration change) and widen the margin to match. Careful: `terrain.vert.glsl` is shared with the canopy material (`TerrainMaterial.ts` ~124/134), whose skirts are deliberately short (`TerrainChunk.ts` ~113) — don't lengthen those. Verify at 5× over steep terrain (Schlossberg-like slopes).
- [x] (9f73ce4) **R0.6 Persist overlay + forest state in the URL hash** (README known gap) — extend the hash format backwards-compatibly (extra trailing fields: overlay key, opacity, forest mode). Note: overlay/forest state lives in `Terrain` (`getOverlay()`/`setOverlay…`, `setForest()`), not in the `Store` that `bindHash` reads — either move it into `AppState` (preferred: one source of truth, source-tagged writes) or bridge it explicitly.
- [x] (9f73ce4) **R0.8 `build.py` drops manifest keys it doesn't own** — `build.py` (~364–427) rebuilds `manifest.json` and only carries over `xyz`; re-running `build` would delete `vectors`/`models`/`candidates` and reset `attribution`. Make it read–modify–write (keep unknown top-level keys, merge attribution sets). **Must be done before F10** (first item adding manifest keys from another step). Add a pytest.

Acceptance: R0.1–R0.6 + R0.8 fixed with tests where logic is pure; verify.sh green; one commit "R0: hardening". **Done 2026-11-01 (commit 9f73ce4):** verify.sh green (vitest 12 files/100, tsc + vite build, pytest 15).

## M5 — Orientation layers on the Karlsberg AOI, then grow

### [x] (cadd9cc) F10 OSM streets/paths draped in 3D
- **Why:** distinguish known paths from unmapped hollow ways (use case U5).
- **Approach:** lead first adds an optional `vectors` section to `docs/data-contract.md` and `app/src/data/manifest.ts`. Pipeline `osm.py <aoi>` (new `osm` step in `run.sh`; needs R0.8): one Overpass bbox query for AOI + buffer (covers the RLP side too), cached in `data/raw/osm/`; highways/tracks/paths/railways/waterways/barriers; project to EPSG:25832, clip, densify to ≤ 2 m, write `vectors/osm.geojson` (UTM coords, properties: kind, name, highway, tracktype) + merge `vectors.osm` into the manifest. Generated GeoJSON stays out of git like all data (reproducible from the cached Overpass response). Renderer (`app/src/vectors/`): pure `drape.ts` (local coords + true height per vertex from HeightQuery as attribute), line meshes sharing `terrain` `uExag/uHRef` uniforms, exaggeration in the vertex shader (same formula), lift 0.3 m × exag + `polygonOffset`; styles by kind; panel toggle "Wege (OSM)" with key **`O`**, off by default for discovery. OSM attribution is already hard-coded in the footer (`features.ts buildAttribution()`), so still check it's shown when the layer is on.
- **Acceptance:** lines lie on the hollow-way/road relief at 1× and 5×, no z-fighting at oblique views, ≥ 60 fps, attribution includes OSM.
- **Done 2026-11-01 (v0.8, commit cadd9cc):** 590 ways; vertex heights = `heightAt` ± 0.3 mm; on relief at 1×/5× (screenshots `docs/screenshots/f10-f12-r2-*`); ≤ 0.95 % line-pixel flicker at grazing views; 2.74–2.99 ms/frame sync with layers on (vsync pacing not measured); footer has `© OpenStreetMap-Mitwirkende, ODbL`.
