## 1. Vision

A browser-based 3D explorer for the new Saarland LiDAR data. You fly like a drone over the bare-earth terrain (three.js) and discover what is hidden beneath the forest canopy: old streets and hollow ways, house foundations, bunkers, walls, moats (Burggräben), pits/craters (Löcher) and other non-natural shapes. A synchronized 2D map (Leaflet + OpenStreetMap) gives orientation, context and cadastral information (Flurstücke / Flurnummern).

**Focus areas**
- **Schloss Karlsberg** (Homburg-Sanddorf, Karlsberg forest; ~49.335 N, 7.379 E) — *first focus tile.* Note: the site straddles the Saarland / Rheinland-Pfalz border (Karlslust is partly in RLP).
- **Kirrberg** (Homburg district) incl. Merburg castle ruin.
- **Homburg** centre incl. Schlossberg (Hohenburg / Vauban fortress, Schlossberghöhlen).

## 2. Goals & Non-Goals

### Goals
1. **Discover relicts under forest** — relief visualizations tuned for anthropogenic micro-topography (±0.2–1 m features).
2. **Feel of flight** — smooth drone-style free camera, low and slow over the forest floor, fast at altitude.
3. **Orientation** — always know where you are: synced Leaflet/OSM minimap, OSM streets draped in 3D, Flurstücke on demand.
4. **Capture findings** — pin candidate relicts with notes, see them on the map, export as GeoJSON.
5. **Fast iteration** — small focus area first, a reproducible data pipeline, then grow.

### Non-Goals (for now)
- Whole-Saarland coverage / national-scale streaming.
- ~~Public hosting with shared find locations (anti-looting, see §10).~~ → dropped 2026-11-02: the user decided to publish on GitHub Pages under the Open-Kirrberg org, relict candidates included (see §9, §10).
- Photorealism (orthophoto is an optional layer, not the default look).
- Automatic relict detection in the MVP (→ phase 2).
- ~~Mobile/touch-first UX.~~ → dropped 2026-11-01 (F20): the user asked for phone use; desktop stays the full layout, phones get a simpler one (see §9).

## 5. Technical Approach

> Detail: `research/02-tech-stack.md` (architecture diagram §7, pipeline §2, libraries §8).

### 5.1 Data Pipeline (build time)
- **MVP: Python via `uv`** (rasterio wheels bundle GDAL; numpy, rvt-py, Pillow, pyproj, morecantile). No PDAL needed, because DTM *and* DSM come as ready GeoTIFFs. **Docker (conda-forge GDAL 3.13 + PDAL 2.10)** is only introduced for the phase-2 point-cloud work.
- Tile fetching: range-request extraction of single tiles from the LVGL county ZIPs + direct RLP downloads; raw data cached in `data/raw/` (git-ignored).
- Output format is fixed in **`docs/data-contract.md`**.
- Steps: mosaic source tiles → crop AOI **on the native 1 m grid (no resampling)** → (optional) PDAL: 0.5 m DTM + canopy-height model (CHM) from LAZ → RVT: SVF, openness, SLRM, MSRM, VAT → `make_chunks.py`: **Terrarium-PNG height chunks** (4 mm precision, avoids terracing) + WebP relief textures + `manifest.json` → `gdal2tiles` EPSG:3857 XYZ overlays for Leaflet.
- OSM via Overpass fetched **once per AOI** and cached in `data/raw/osm/`; the generated GeoJSON stays out of git like all data (reproducible via `./run.sh <aoi> osm`).

### 5.2 3D Rendering (three.js)
- **three.js r187 + small custom terrain engine** (WebGLRenderer): chunked quadtree heightmap, 500-cell chunks on a level pyramid 1/2/4/8/16 m (contract v2), screen-space-error selection, prioritised job queue, LRU eviction under a 600 MiB GPU budget (✅ v0.9), mesh LOD 1–10 m within a chunk, skirts against cracks (depth per chunk from measured LOD edge deviation, scaled with exaggeration — v0.7; also covers neighbours up to 4 levels coarser — v0.9), worker-decoded tiles.
- `TerrainMaterial` (GLSL): vertex-texture displacement; **per-pixel normals from the full 1 m height texture** → relief detail independent of mesh density.
- **Plan B:** Giro3D 2.0 (three.js-based, arbitrary CRS, COG elevation, COPC) — one-day spike if the custom engine stalls.
- Float precision: local origin (E0/N0), never raw UTM in float32.

### 5.3 Relief Visualization for Relict Detection
> Detail: `research/03-archaeology-visualization.md` Part A.

| Mode (UI label DE) | Technique | Where computed |
|---|---|---|
| *Schummerung* | Hillshade, adjustable sun azimuth/elevation, multi-directional | Live shader |
| *Hangneigung* | Slope | Live shader |
| *Lokales Relief* | SLRM (h − low-pass, radius ~10–20 m), diverging colormap | Live shader / GPU pass |
| *Himmelssicht* | Sky-View Factor | GPU pass on parameter change or RVT precomputed |
| *Offenheit ±* | Positive / negative openness | GPU pass or RVT |
| *VAT (Standard)* | Blend of hillshade, slope, openness, SVF — **default discovery look** | Blend in shader from layers |
| *Luftbild* / *Karte 1840* | DOP20 orthophoto / historic map ("Bilder" row, base or overlay; ✅ v0.10) | Texture (`rgb` layer, sRGB) |

Plus: vertical exaggeration slider (1×–5×), sun controls.

### 5.4 Forest / Canopy
- MVP: **CHM raster** (DSM − DTM) as a second mesh/displacement with opacity slider ("Wald ein/aus/transparent").
- Phase 2: classified point cloud for focus areas only; height-above-ground clip, "X-ray lens". ✅ v0.12 without Potree: custom `sle-pts-v1` 100 m tiles drawn with our own three.js `ShaderMaterial` (see §9, F16).

### 5.5 Streets & Houses
- **OSM streets/paths draped** onto the terrain (true height per vertex as an attribute — baked by the pipeline since v0.9, HeightQuery as fallback — exaggeration applied in the vertex shader), toggleable (key `O`). ✅ v0.8: screen-space ribbons, lift 0.3 m·exag + camera pull + `polygonOffset`; v0.9: parsed in a worker, meshes only within a radius of the camera.
- **Buildings:** ✅ v0.10 (key `G`, default on): LoD2 CityGML parsed with lxml (no Java), triangulated with mapbox-earcut, one hand-written glb per level-0 chunk in the local frame; wall bottoms extended to the DTM; clay `ShaderMaterial` sharing the terrain's exaggeration/sun/fog uniforms; streamed within 2 km. Footprints also give the R0.7 `bldg` mask that keeps the canopy off roofs.
- **Flurstücke + Flurnummern:** Leaflet INSPIRE CP WMS overlay (live); 3D: build-time paged WFS (≤10 000 features/page; overall AOI: 66 653 deduplicated lines, 42 MB + 23 525 labels, 5.2 MB) → GeoJSON → draped lines + Flurnummer labels (✅ v0.8, key `F`; RLP side via RLP WFS 519; labels within 300 m, decluttered since v0.9; parcel line meshes within ≈ 2.1 km; marker form prefers the local parcel data). Avoid "freie Liegenschaftskarte SL" (not openly licensed).
- **Historic maps:** build-time download of "WMS SL Historische Karten" (cookie jar) as georeferenced images on the native grid → Leaflet overlay + optional 3D terrain texture ("Karte 1840"). ✅ v0.10: 1836–41 + 1935–40 as `rgb` layers + XYZ.

### 5.6 2D Map (Leaflet / OSM)
- **Leaflet 1.9.4** + OSM base map; `proj4` for EPSG:25832 ⇄ WGS84 (Proj4Leaflet not needed).
- Layers: OSM, own relief XYZ overlays, historic-map XYZ (`xyz.hist_*`, v0.10), DOP20 WMS (live, off by default, Saarland only, v0.10), Flurstücke WMS, POIs, user pins, AOI outline (+ dashed focus-area outlines "Schwerpunktgebiete", v0.9).
- Sync: camera = rotated marker, view footprint = polygon from frustum rays hitting terrain; **map click → `flyTo`**; URL hash holds camera pose, base layer, overlay key/opacity and forest mode (shareable bookmarks; v0.7).

### 5.7 Flight Controls
- **DroneController** (custom, on PointerLockControls): WASD + mouse, Q/E or Space/Shift up/down, speed scales with height above ground (AGL), minimum clearance (terrain following), scroll = speed, gamepad support.
- Non-pointer-lock drag-look fallback; optional orbit "inspect" mode (camera-controls) around a clicked point.

### 5.8 Project Setup
- **Vite 8 + TypeScript**, `pnpm`; static tiles in `public/data/`; runs locally (`pnpm dev`). Pinned dependency versions.
- UI: German labels, code/docs in English. lil-gui for the first iteration of layer controls.

## 10. Risks
| Risk | Mitigation |
|------|-----------|
| Height quantization / resampling creates fake or hides real relicts | Terrarium encoding, crop on native grid, worker decode without color-space conversion |
| Custom terrain engine effort | MVP with fixed LOD + skirts; Giro3D plan B |
| Public site shows relict candidates (looting risk, user decision 2026-11-02) | Candidates are labelled as unchecked hypotheses with reasons and scores; disclaimer "Schauen, nicht graben" before first use; no digging/detector guidance; user markers, reviews and *Mein Standort* never leave the browser; report flow points to the Landesdenkmalamt |
| Data volume when growing AOI | Start 2×2 km; overview levels + LRU streaming; overall AOI = 1.0 GB plain files (v0.9), 1.3 GB with buildings/ortho/historic maps (v0.10), 1.4 GB with point clouds (v0.12), served from one data dir (v1.0), PMTiles only above 2 GB; point clouds only for focus areas |
| Saarland data format/availability surprises (XYZ quirks, LAZ/LoD2 not open) | M0 data spike first; fallbacks (CHM from DOM, OSM buildings) |
| False positives (uprooted-tree pits, inland dunes near Karlsbergweiher, natural sinks) | Treat markers as hypotheses; compare with historic maps and known POIs; F15 candidates are scored with reasons and need a manual review step (v0.11) |
| **Legal / ethical** (SDschG Saarland §§ 3, 8, 16, 18, 28; DSchG RLP; UXO at bunkers) | Disclaimer "Schauen, nicht graben"; keep candidates private; no digging/detector guidance; report to Landesdenkmalamt |
| Licensing (DL-DE BY 2.0, ODbL, OSM tile policy) | Attribution in UI + manifest; no bulk OSM tile scraping |
